# Project story template

Fill one file (or one section) per launch story. Keep founder/hackathon work distinguishable from Zatroz client work.

**Story status on site:** `Client work` · `Live product` · `Prototype` · `Research concept`  
**Editorial status:** `Missing` · `Draft` · `Needs review` · `Approved`

---

## Template fields

| Field | Instructions |
| --- | --- |
| Title | Public project name |
| Slug proposal | Lowercase kebab-case URL segment for `/work/[slug]` |
| Status | One accurate label from the list above |
| Problem | Business problem in plain English |
| Audience | Who experiences the problem |
| Actual team / owner | Real people or team name |
| Zatroz contribution | What Zatroz (or a founder under Zatroz) actually did |
| Solution | What was built |
| Features | Key user-facing capabilities (honest list) |
| Stack | 3–5 meaningful technologies |
| Screenshots | Asset IDs; PII removed; permission recorded |
| Verified results | Outcome + measurement method/time if numerical |
| Links | Live URL or demo only if allowed |
| Publication permission | Client/owner approval status |
| Limitations | What is unfinished, unverified, or out of scope |
